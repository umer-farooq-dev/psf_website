The two decisions that shaped the build

1. The price rule is enforced in the helpers, not the templates

Fifteen templates render prices. Rather than edit all fifteen, the guard sits inside getProductPriceByType() and getPriceRangeWithDiscount(), so every existing template — and any template added later — gets « Contactez-nous pour le prix » for free.

The cart guard sits in CartManager::add_to_cart() rather than a controller, so a crafted request that skips the UI is blocked too.

2. Nothing was deleted from 6valley — only wrapped

Menus and homepage blocks are hidden behind psfMenu() and psfHomeSection() guards. Core files gained guards, never deletions. That keeps the footprint small enough to survive a 6valley update, and lets the client switch anything back on from the panel.

Two pre-existing problems that were fixed

The whole site was set to noindex, nofollow

app.blade.php carried a hardcoded robots meta tag telling search engines not to index anything, plus a second empty one from the SEO partial. Google would never have listed the shop, and nothing would have signalled it.

Every page now emits a single correct tag, driven by a panel switch (psf_search_indexing) that defaults to on.

Two robots.txt files, one pointing at a stranger's dev server

The served file is the project root one; public/robots.txt still referenced 127.0.0.1:8000. Both are now in sync, built from APP_URL, and also block /admin/, /cart and /checkout.

Known, not fixed

A 6valley bug: a product whose discount_type is NULL crashes the price helper. It only surfaces for products created outside the admin form (the form always sets it), so it does not affect normal use. Left alone deliberately — fixing it means touching core price logic for a case that cannot occur in practice.

Also: php artisan route:list fails because of a Firebase placeholder key in the shipped config. Web pages are unaffected; it only breaks that one CLI command.

Before it goes live

Ordered by consequence. The first two are the ones that bite.

  • Set APP_DEBUG=false in .env. It is currently true, which is why Debugbar output — including session contents and the login captcha value — is visible in page source.
  • Update APP_URL to the real domain, then regenerate robots.txt so its sitemap line is correct.
  • Generate the sitemap from SEO Settings once real products exist — sitemap.xml is currently 0 bytes.
  • Change the admin password. During testing I temporarily reset it and restored the original hash each time, so your current password still works — but it should be rotated before launch regardless.
  • Paste the Google Search Console code into SEO Settings → Webmaster Tools. The field is already wired into every page's <head>.
  • Delete the demo data — four test quote requests are sitting in the devis inbox so you can see the screen populated.

Still needed from the client

  • CinetPay merchant account — blocks phase 4 entirely. Nothing can be built or tested for online payment until these credentials exist.
  • Confirm the phone numbers. The brief contains two conflicting sets. The site currently uses +226 78 24 48 89.
  • Opening hours — placeholder values are in place; the client needs to confirm the real ones.
  • Brand logos for the Marques block.
  • Google Maps embed for the exact shop location.
  • Product catalogue. The client is adding these; there are currently 2 test products and 0 categories.
Worth knowing

Product schema fields for image and category were verified using temporary test data, which was then removed — there are no real categories or product images in the database yet. Worth one look once the client's real catalogue is in.
